## 一、五分钟上手

| 步骤 | 操作 | 位置 |
|---|---|---|
| 1 | 打开 `http://localhost:7200`，注册并登录 | 登录页 |
| 2 | 点「接口设置」，填入大模型地址与密钥 | 首页右上角 |
| 3 | 点「填入纪要范本」自动填一段示例速记 | 首页文本框右上 |
| 4 | 点「梳理会议备忘」，等进度条走完 | 首页底部按钮 |
| 5 | 自动跳转到结果页，查看决议、待办与议题 | `/result/xxxx` |

跑通一次后，把示例内容换成你自己的会议内容即可。

> 💡 第一次用建议直接走「填入纪要范本」这条路——不用准备音频、不用配转写密钥，几秒就能看到成品效果。

## 二、账号：注册、登录与安全

### 注册

| 项目 | 规则 |
|---|---|
| 用户名 | 3–24 位**字母、数字或下划线**，或合法邮箱地址 |
| 密码 | 8–64 位，且**必须同时包含字母和数字** |
| 图形验证码 | **必填**，5 位字符（数字 + 大写字母，不含 0/O/1/I/L 等易混字符） |

验证码图片不清晰时点「换一张」刷新。验证码 **300 秒有效、用一次即失效**——如果这次提交失败（比如用户名被占用），需要重新获取一张再提交。

**第一个注册的账号会自动成为管理员**，并认领系统中历史遗留的存量会议数据；之后注册的账号则是独立的新用户，各自看到自己的内容。

### 登录

- 正常输入用户名密码即可
- **连续输错密码 2 次后**，登录框会多出一行图形验证码（这是账号保护机制，不是故障）
- 同一账号**连续失败 5 次**会被锁定 **15 分钟**，到期自动解锁，无需联系管理员
- 同一 IP + 用户名在 15 分钟内失败超过 5 次，也会被临时限速

### 登出与改密

- 点右上角「登出」：服务端会**立即吊销本次会话**，即便有人拿到了旧 Cookie 也无法再用
- 改密入口在「接口设置」弹窗底部：新密码同样要求 ≥8 位含字母数字。**改密成功后，你在其他设备/浏览器上的登录会全部下线**，当前设备保持在线

> 若你接手了别人交付的账号，请**首次登录后立即修改密码**。

## 三、配置接口：让 AI 能干活

点首页右上角「接口设置」。所有配置**保存在服务端**，换浏览器登录同一账号无需重填。

### 3.1 语言模型（必填）

用于：纪要提炼、待办萃取、纪要问答。三项都要填：

| 字段 | 说明 |
|---|---|
| **接口地址（Base URL）** | 服务商的 OpenAI 兼容地址，如 `https://api.deepseek.com` |
| **接口密钥（Key）** | 以 `sk-` 开头的密钥串 |
| **模型标识（Model）** | 模型名，如 `deepseek-chat` |

**推荐做法**：先点服务商预设按钮，地址与默认模型会自动填好，你只需补上密钥；再点「获取模型列表」，从下拉里挑一个实际可用的模型即可（这一步同时验证了地址与密钥是否正确）。

内置预设服务商：

| 服务商 | 接口地址 | 默认模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| 月之暗面 (Kimi) | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |

### 3.2 语音转写（用录音/音频时必填）

**只有在使用「音频转写」或「现场收音」时才需要**。纯文字录入可以跳过这一节。

| 字段 | 说明 |
|---|---|
| 接口地址 | 转写服务的 OpenAI 兼容地址，如 `https://api.siliconflow.cn/v1` |
| 接口密钥 | 对应服务的 Key |
| 转写模型 | 如 `whisper-1`、`FunAudioLLM/SenseVoiceSmall` |

如果转写服务和语言模型是**同一个服务商**，勾选弹窗里的「直接复用上方的大模型接口地址与密钥」，省去重复填写（只需再填转写模型名）。

### 3.3 关于密钥安全

- 密钥以 **AES-256-GCM 密文**存入数据库，页面与接口**永远不会回传明文**，只显示尾 4 位用于确认
- 保存后再次打开设置，密钥框会**留空**——留空表示「保留原密钥不变」，要更换才需要重新输入
- 每位用户**各自独立配置自己的密钥**（BYOK），互不可见

> 首页「接口设置」按钮上：显示绿点 = 已配置可用；显示「待配置」= 还没填。

## 四、录入会议：三种方式

首页顶部的三个标签页，任选一种：

### 4.1 文字实录（最简单，推荐日常使用）

把会议发言、讨论提纲、聊天记录粘贴进文本框，**至少 5 个字**。右下角实时显示字数。

> 想快速体验，点文本框右上角的「填入纪要范本」自动填一段示例。

### 4.2 音频转写

上传已有的录音文件，系统先转成文字再提炼纪要。

- 支持格式：`.mp3 .wav .m4a .aac .flac .ogg .opus .webm .amr` 等常见音频
- **单个文件不超过 50MB**
- 转写本身有 **10 分钟超时**上限，超长音频建议先切分

### 4.3 现场收音

点「现场收音」→ 浏览器请求麦克风权限 → 开始录制 → 录完自动切到「音频转写」模式并带上录音文件，接着点「梳理会议备忘」即可。

> 浏览器录音在部分环境会存为 `webm/opus`，属正常现象，不影响转写。

### 4.4 选择场景侧重

录入框上方的四个按钮决定 AI 的整理侧重点：

| 场景 | 适用情形 | 整理侧重 |
|---|---|---|
| **工作例会** | 常规周会、项目例会 | 各项进展、问题与下一步计划 |
| **日常同步** | 站会、晨会 | 昨日完成、今日目标、卡点与求助 |
| **专题研讨** | 头脑风暴、方案评审 | 观点碰撞、方案争议焦点、认可的尝试方向 |
| **商务商谈** | 客户沟通、合作洽谈 | 客户诉求、双方承诺、价格与合作边界、对接人 |

选好场景再提交，纪要的"味道"会明显不同——商务商谈会自动突出"诉求与承诺"，站会则突出"卡点"。

## 五、读懂结果页：纪要六大板块

提交后自动跳转到结果页，内容按以下顺序组织：

| 板块 | 内容 |
|---|---|
| **会议标题区** | 会议类型标签、日期时间、字数统计；鼠标悬停标题右侧点「✎ 修改」可改名 |
| **一、会议核心结论与定案** | 分条列出的决议要点 |
| **二、待办事项与责任人** | 每条含负责人与截止日期，**点击整条即可勾选完成**，状态自动存服务端；顶部显示「已完成 x / y」 |
| **三、具体讨论议题与发言记录** | 按议题分组，每个议题下是发言要点 |
| **四、注意事项与潜在风险** | 仅在识别到风险时出现 |
| **五、查阅发言速记全文** | 可折叠，展开查看原始全文（便于核对 AI 是否漏掉内容） |
| **六、问答助手** | 展开后可对本次会议内容追问，见第八节 |

> 勾选待办是**持久化**的：关掉页面、换设备打开，勾选状态都还在。

## 六、导出与分发

结果页顶部一排按钮，按使用场景选：

| 按钮 | 用途 | 说明 |
|---|---|---|
| **复制全文（直接发微信/企微）** | 群内汇报 | 一键生成带编号、带 @负责人、带截止日期的纯文本，粘贴到微信/企微即排版整齐 |
| **导出 Word** | 正式存档 | 下载 `.docx` 文件，含决议、待办、发言速记，可直接打印或转发 |
| **生成卡片** | 快速预览 | 弹出「纪要便签预览」卡片，可一键复制精简版摘要 |
| **分享** | 给同事看 | 复制本篇纪要的页面链接（**对方需登录并拥有该篇纪要的访问权限**） |

## 七、历史纪要管理

点首页右上角「历史纪要」打开右侧抽屉：

- 默认展示最近 **25 篇**，含标题、摘要、时间、会议类型与待办数量
- **点击任意一条** → 进入该篇结果页
- 鼠标悬停某条 → 右侧出现 **✕** → 点击并确认即可删除（删除不可恢复）

每次成功整理一篇纪要，系统都会自动归档，无需手动保存。

## 八、纪要问答助手

在结果页底部展开「向纪要助手提问」，就能针对**本次会议的全部内容**提问，例如：

- "会议最终决定了哪三件事？"
- "周三去印厂的是谁？"
- "客户对价格的态度是什么？"

助手会结合这篇纪要的完整上下文回答，**不会**看到你其他的会议。提问需要已配置大模型密钥。

## 九、写出好纪要的技巧

1. **带上人名与时间**。写作「陆文周三上午 10 点去印厂看色」，比「有人去印厂」更容易被提炼成一条完整的待办（含负责人与截止日期）。
2. **把决议和讨论分开说**。「明确三项安排：1…2…3…」这类表述，会被准确归入「核心结论与定案」。
3. **速记不用润色**。口语化、有错别字都没关系，重点是信息完整——提炼是 AI 的活。
4. **场景选对**。同样是内容，选「商务商谈」会突出诉求与承诺，选「专题研讨」则突出争议与结论。
5. **注意时长与篇幅**。极长的录音建议切成几段分别整理，既避开转写超时，也能让提炼更聚焦。

## 十、常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 点提交后直接弹出设置窗 | 还没配置大模型密钥 | 在「接口设置」里填入地址、密钥、模型 |
| 提示「读取接口设置失败，请确认本机数据库服务已启动」 | 数据库未启动或连接串错误 | 请联系运维确认 MySQL 已启动、`DATABASE_URL` 正确 |
| 上传音频后提示「未配置语音转写 API 密钥」 | 转写与语言模型是**两套**配置 | 在设置弹窗下半部分补填 ASR 地址/密钥/模型 |
| 提示「录音文件过大」 | 超过 50MB | 压缩或切分音频后重传 |
| 转写提示超时 | 超过 10 分钟处理上限 | 换更短的音频，或检查网络 |
| 提示「会议内容太短」 | 文字不足 5 字 | 补充内容后重试 |
| 提示「模型返回的内容格式不符合预期」 | 所选模型不支持结构化输出 | 换用列表中其他模型（推荐 DeepSeek / GPT 系列） |
| 登录时多出验证码输入框 | 该账号连续失败 2 次的防护 | 正常输入 5 位字符即可（不分大小写） |
| 提示「账号已临时锁定」 | 连续失败 5 次 | 等 15 分钟自动解锁 |
| 登录后被反复弹回登录页 | 本地 http 环境误开了 `COOKIE_SECURE` | 请运维删除该变量或置为 `0` |
| 换张验证码图片后仍报验证码错误 | 验证码是一次性的，图片与输入框需成对使用 | 刷新后立刻输入最新一张图上的字符 |
| 想给同事看纪要，对方打不开 | 数据按用户隔离，越权访问返回 404 | 可改用「导出 Word」或「复制全文」分发 |

## 附：数据与隐私说明

- 你的会议内容存放在本机 MySQL 数据库，仅通过你自己的账号可见
- 大模型 / 转写请求会把你输入的内容发送到**你自己配置的服务商**——请按公司合规要求选择服务商
- API 密钥加密存储，任何人（包括管理员）都无法从接口读到明文
- 换机备份时，请连同数据库与 `.data/`、`data/` 下的密钥文件一并迁移，否则已保存的密钥将无法解密
