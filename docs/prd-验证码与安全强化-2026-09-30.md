# 增量 PRD：验证码功能 + 安全强化包

> 版本：增量迭代 v3｜撰写：产品经理 许清楚（Xu）｜状态：待架构师评审
> 前提：认证体系已上线（账号密码 + 开放注册 + 无状态签名 Cookie + 限速 + 数据隔离）。本文档只描述**验证码 + 安全强化**增量。

## 1. 项目信息

| 项 | 内容 |
|---|---|
| Programming Language | Next.js 16 App Router + React 19 + Tailwind 4（沿用现有栈） |
| Project Name | meeting-ai-captcha-security |
| 版本 | 增量迭代 v3（基于已有认证体系） |

**原始需求复述**：在已有账号密码认证体系上，新增自研图形验证码（注册必加、登录自适应触发），并交付基础安全强化包：会话服务端吊销、账号级失败锁定、安全响应头、CSRF Origin 校验。三项方案均已拍板，本文档不做方案选型讨论。

## 2. 产品定义

### Product Goals

1. **防机器人**：阻断脚本批量注册与撞库攻击，且零外部依赖、零成本（自研图形验证码）。
2. **无感防护**：正常用户操作路径不被打扰（登录失败 2 次前不出现验证码），精准打击异常流量。
3. **收敛攻击面**：会话可吊销、账号可锁定、传输层与请求来源可校验，补齐认证链路安全短板。

### User Stories

**验证码**
- US-1：作为一个新用户，我在注册时必须输入图形验证码，以便证明我是真人而非脚本批量注册。
- US-2：作为一个登录用户，我在前 2 次登录失败时不受验证码干扰；当失败达到 2 次后，系统自动要求我输入验证码，以便在遭受撞库时精准拦截机器人而正常用户基本无感。
- US-3：作为任何看到验证码的用户，我在看不清时可点击刷新按钮立即更换一张新图，以便不至于因图形扭曲而无法完成操作。
- US-4：作为系统，验证码 token 为一次性使用且设有效期（建议 5 分钟，由架构师定），已使用或过期的验证码提交必须拒绝，以便防止重放。

**会话吊销**
- US-5：作为一个已登出用户，即使我的 Cookie 曾被拷贝，服务端也已将该会话标记失效，拷贝的 Cookie 无法继续访问受保护资源，以便登出语义真正生效。
- US-6：作为修改密码的用户，改密成功后所有设备上的旧会话立即失效（现有 token_version 机制保留），且旧 Cookie 无法再通过服务端校验，以便账号被劫持后可一键夺回。

**账号锁定**
- US-7：作为一个攻击目标账号，当攻击者对同一账号连续登录失败达 N 次（建议 N=5，由架构师定）后，该账号被锁定一段时间（建议 15 分钟，由架构师定），锁定期间即使密码正确也拒绝登录，以便大幅收窄撞库攻击面。
- US-8：作为一个被误锁的正常用户，我无需任何人工介入，等待锁定期满后自动解锁即可重新登录；页面应显示"剩余等待时间"提示而非报错堆栈，以便体验友好且不泄露内部状态。

**安全强化**
- US-9：作为浏览器用户，站点响应携带 X-Frame-Options / X-Content-Type-Options / Referrer-Policy 等基础安全头，以便降低点击劫持与 MIME 嗅探风险。
- US-10：作为站点，所有写操作（POST/PUT/PATCH/DELETE）必须校验 Origin/Referer 同源，异源写请求返回 403，以便阻断 CSRF 攻击。

## 3. 技术规范

### Requirements Pool

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| R1 | 自研图形验证码生成：服务端随机字符 + 扭曲/干扰绘制，返回图片与一次性 token | P0 | 图片可正常渲染；token 唯一且不可预测；生成不依赖任何第三方服务 |
| R2 | 验证码校验接口：一次性消费 + 有效期（建议 5min）+ 大小写不敏感（由架构师定） | P0 | 同一 token 二次提交返回失败；过期 token 返回失败；错误输入后需换新码重试 |
| R3 | 注册流程强制验证码：验证码校验失败则注册请求拒绝 | P0 | 脚本不带/带错验证码注册 100% 被拒；人工正确输入可注册成功（现有 48 用例回归不破坏） |
| R4 | 登录自适应验证码：同账号失败 ≥2 次后，登录请求必须携带有效验证码 | P0 | 首次/第二次失败不要求验证码（正常用户无感）；第 3 次起未带或带错验证码一律拒绝并要求刷新；成功登录后失败计数清零 |
| R5 | 验证码刷新：前端"看不清？换一张"按钮调用重新生成 | P0 | 点击后 ≤1s 展示新图；旧 token 作废 |
| R6 | 会话服务端吊销：登出时服务端销毁会话记录（建议服务端维护会话标识表或版本号，方案由架构师定）；校验时先验签名再验服务端有效性 | P0 | 登出后拷贝旧 Cookie 请求受保护接口返回 401/307；改密后全端旧 Cookie 同样失效；正常登录会话不受影响，7 天过期语义保留 |
| R7 | 账号级失败锁定：同一账号连续失败 N 次（建议 5）锁定 M 分钟（建议 15），与现有 IP 限速叠加生效 | P0 | 锁定期内正确密码也拒绝并提示剩余时间；自动解锁，无需人工；成功登录清零计数 |
| R8 | 安全响应头中间件：X-Frame-Options: DENY、X-Content-Type-Options: nosniff、Referrer-Policy: strict-origin-when-cross-origin（可补充项由架构师定） | P0 | 全站响应含上述头；本地页面无法被 iframe 嵌套（可用浏览器 DevTools 验证） |
| R9 | CSRF Origin 校验：写方法（POST/PUT/PATCH/DELETE）校验 Origin/Referer 与站点同源，异源 403；GET 不校验 | P0 | 同源写请求正常；构造异源 Origin 的写请求返回 403；不影响现有 48 用例 |
| R10 | 登录/注册页验证码 UI：图片展示、刷新按钮、输入框、校验失败自动换新码 | P0 | 与现有 Tailwind 4 风格一致；校验失败提示明确且换新码 |
| R11 | 锁定/验证码状态的前端反馈文案与剩余时间展示 | P1 | 锁定提示含剩余分钟数；不泄露"账号不存在 vs 密码错误"等内部差异 |
| R12 | 回归测试扩充：新增 e-captcha + f-security 用例组并入 run-all.mjs | P1 | 覆盖：验证码一次性/过期/自适应触发边界、吊销即时性、账号锁定解锁、CSRF 异源拒绝、安全头存在性；全部自注入自清理，跑完全绿 |
| R13 | 验证码图片可访问性兜底：提供音频验证码或更强的可换图重试机制 | P2 | 视力障碍用户有替代路径（本期可仅做文档记录，实现留后续） |

**验收总纲**：
- 防机器人有效性：无验证码的自动化注册/撞库脚本 100% 被拒（R3/R4 用例证明）。
- 自适应触发边界：失败 1-2 次无验证码要求，第 3 次起强制，成功登录后重置（R4 用例覆盖边界值）。
- 吊销即时性：登出/改密后下一次请求即失效，无延迟窗口。
- 锁定攻击面收窄：单账号每 15 分钟最多 5 次密码猜测（叠加 IP 限速 15min/5 次），攻击成本提升一个数量级。

### UI Design Draft

- **/register 页**：在密码字段下方新增验证码行——左侧验证码图片（可点击刷新），右侧输入框；提交后校验失败自动刷新图片并清空输入。
- **/login 页**：默认无验证码区域；当响应表明需要验证码（自适应触发）时，动态渲染同样的验证码行；锁定状态下提交按钮上方展示倒计时提示条。
- **样式**：沿用现有认证页卡片布局与 Tailwind 4 设计 token，不新增设计语言。

### Out of Scope（明确不做，留后续迭代）

- 手机短信 / 邮箱验证码
- 第三方验证码服务（hCaptcha、reCAPTCHA、腾讯云验证码等）
- 审计日志
- 管理员封禁账号 / 强制下线（管理员后台仅保留现有只读用户列表）
- 人工解锁通道（邮箱验证解锁 / 管理员解锁）——保持全自动解锁语义

### Open Questions（均标注责任人）

1. 验证码有效期具体取值（建议 5 分钟）、字符集（建议纯数字 4-5 位或数字+大写字母）、大小写敏感性——**由架构师定**。
2. 服务端会话吊销的实现载体（内存 Map + 重启失效容忍 vs 持久化到 MySQL sessions 表）——**由架构师定**，倾向 MySQL 以保证自托管重启后吊销不丢失。
3. 账号锁定的 N/M 参数（建议 5 次/15 分钟）及是否与 IP 限速共享计数——**由架构师定**。
4. 自适应触发计数维度（按账号 vs 按 账号+IP 组合）——**由架构师定**，建议按账号以覆盖分布式撞库。
5. 安全头是否追加 Content-Security-Policy 基础版——**由架构师定**（涉及 Next.js 内联脚本约束，风险较高，本期可不做）。
