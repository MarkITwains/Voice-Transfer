# 会议 AI（meeting_ai）增量 PRD —— 登录服务与多用户支持

> 版本：v1.0（增量）｜撰写：产品经理 许清楚（Xu）｜状态：待架构师评审
> 前提：数据层已完成 MySQL 化（本机 MySQL 9.7.2，库 meeting_ai，三张表由 app/lib/bootstrap.ts 自动创建）。本 PRD 只描述**登录与多用户**增量变更，转写/纪要/导出等 AI 功能逻辑与前端交互流程不变。

---

## 1. 项目信息

- **项目名称**：meeting_ai（增量迭代：登录服务与多用户支持）
- **技术基线**：Next.js 16 App Router + React 19 + Tailwind 4；MySQL 9.7.2（127.0.0.1:3306）；现有 API 全部无鉴权
- **定位变更**：从「单人自用、全局共享」升级为「面向多用户的服务」，核心原则：**数据隔离 + 用户自带密钥（BYOK）**
- **变更范围**：新增认证体系 + 用户表 + 数据归属改造 + 现有 API 鉴权；不改动 AI 功能本身

---

## 2. 产品目标

1. 提供账号密码登录（bcrypt 加密存库）+ 开放注册，任何人可自助创建账号使用服务。
2. 实现多用户数据完全隔离：会议数据、API 密钥（BYOK）按用户归属，互不可见、互不影响。
3. 保护未登录访问：页面跳转登录页、API 统一返回 401；首个注册用户自动成为管理员并继承存量 4 条会议。

## 3. 用户故事

| # | 用户故事 |
|---|---------|
| US-1 | 作为新用户，我希望用自己的账号密码完成注册并立即登录，以便无需他人协助即可开始使用转写和纪要功能。 |
| US-2 | 作为已登录用户，我希望在另一台设备/浏览器上登录同一账号，以便看到与我账号绑定的全部历史会议和我配置的 API 密钥（免重配）。 |
| US-3 | 作为用户 A，我希望看不到用户 B 的任何会议、纪要和密钥配置，以便我的隐私与工作内容不被他人访问。 |
| US-4 | 作为用户，我希望配置自己的 LLM/ASR 密钥并仅对我的调用生效，以便用量与费用由我自己的账号承担（BYOK）。 |
| US-5 | 作为第一个注册的用户，我希望自动获得管理员身份并继承现有 4 条历史会议，以便存量数据不丢失且我拥有后续管理能力。 |
| US-6 | 作为未登录访客，我希望访问任何页面都被引导到登录页，以便清楚知道需要先注册/登录才能使用。 |
| US-7 | 作为已登录用户，我希望手动登出，且会话在长时间不操作后自动过期，以便在公用电脑上使用后账号不被他人冒用。 |

## 4. 需求池

## 5. 明确不做（Out of Scope）

1. **手机号/邮箱验证码注册**：不做邮箱/手机验证，注册仅需用户名+密码。
2. **OAuth / 第三方登录**：不做微信、Google、GitHub 等第三方登录。
3. **忘记密码自助找回**：因无邮箱/手机渠道，本期不做；忘记密码由管理员处理（人工）。
4. **多租户/组织架构/团队空间**：不做部门、团队、共享会议空间。
5. **配额、计费、用量统计**：不做付费墙与调用配额限制（BYOK 模式下用户自担费用）。
6. **管理员删除用户/重置他人密码等管理操作**：本期管理员仅为角色标记 + 只读用户列表，操作能力后续迭代。
7. **AI 功能逻辑与页面布局改动**：转写、纪要、思维导图、问答、导出逻辑不变；主界面仅增加登录态入口。

## 7. 验收标准

1. 未注册访客访问任意页面被重定向到登录页；直接调用任意现有 API 返回 401。
2. 开放注册：新用户可用用户名+密码自助注册（弱密码被拒绝）并登录使用全部功能。
3. 隔离：用户 A 登录后仅能查到自己的会议与密钥配置；通过伪造 meeting id 访问他人会议返回 404/403，无横向越权。
4. BYOK：用户各自配置的 LLM/ASR 密钥仅对其本人调用生效；数据库中密钥为 AES-256-GCM 密文，GET /api/settings 返回脱敏值。
5. 会话：登录后刷新/换页面保持登录态；登出后访问受限资源回到登录页；会话过期后同样回到登录页。
6. 存量迁移：首个注册用户为管理员角色，登录后可见原 4 条历史会议，迁移仅执行一次。
7. 限速：高频登录失败/注册请求被限速或锁定，响应中无账号存在性信息泄露。
