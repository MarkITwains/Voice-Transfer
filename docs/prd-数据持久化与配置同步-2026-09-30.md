# 会议 AI（meeting_ai）增量 PRD —— 数据持久化与配置同步

> 版本：v1.0（增量）｜撰写：产品经理 许清楚（Xu）｜状态：待架构师评审
> 本 PRD 只描述**增量变更**，既有功能（转写、纪要生成、思维导图、待办提取、AI 问答、Word 导出）逻辑不变，不在赘述范围。

---

## 1. 项目信息

- **项目名称**：meeting_ai（增量迭代：数据层重构）
- **技术基线**：Next.js 16.2.10（App Router）+ React 19 + Tailwind 4，dev 端口 7200，Windows 11 本机自托管
- **变更范围**：数据存储层 + 设置存储层 + 相关 API 路由的数据访问方式；**不涉及** AI 功能逻辑与前端交互流程的改动

---

## 2. 产品目标

1. 将会议数据从「内存 Map + JSON 文件」迁移到真正的数据库（MySQL 或 PostgreSQL，选型由架构师定），消除无事务、无并发保护的数据丢失风险。
2. 将 API 密钥与模型配置（LLM + ASR 两套）从浏览器 localStorage 迁移到服务端数据库，实现换浏览器/换设备后数据与配置全局一致、免重配。
3. 清理重复的 store 实现文件，统一为单一数据访问入口，降低后续维护成本。

---

## 3. 用户故事

| # | 用户故事 |
|---|---------|
| US-1 | 作为使用者，我在另一台电脑/浏览器上打开会议 AI，希望立刻看到全部历史会议与纪要，以便随时查阅而不受设备限制。 |
| US-2 | 作为使用者，我换浏览器访问时，希望 API 密钥与模型配置自动生效，以便无需重新填写密钥即可直接发起转写和总结。 |
| US-3 | 作为使用者，我在两个浏览器窗口同时操作（如一边删除旧会议、一边查看列表），希望数据保持一致、不出现覆盖丢失，以便放心并发使用。 |
| US-4 | 作为使用者，我首次升级到新版本时，希望原有的历史会议数据和 API 设置被自动迁移进数据库，以便平滑升级、无感切换。 |

## 4. 需求池

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| R1 | 引入数据库服务（MySQL 或 PostgreSQL，选型由架构师定） | P0 | 新增会议表（meetings）、设置表（settings）等；提供本机部署与初始化脚本。 |
| R2 | 会议数据落库：/api/meetings（GET/DELETE/PATCH）等路由全部改为经统一数据访问层读写数据库 | P0 | 移除内存 Map + JSON 整体覆写模式；写操作须具备并发安全（事务或行级锁，由架构师定）。 |
| R3 | API 设置入库同步：LLM 与 ASR 的密钥、模型配置存入服务端数据库 | P0 | 前端 localStorage 不再作为配置来源（可保留为缓存）；设置读写走新的 /api/settings 路由。 |
| R4 | 存量数据一次性迁移：`.data/meetings.json` 及浏览器 localStorage 中的旧设置导入数据库 | P0 | 提供迁移脚本或启动时自动迁移逻辑；迁移幂等，重复执行不产生脏数据。 |
| R5 | 清理重复 store 文件：`app/store.ts` 与 `app/lib/meetingStore.ts` 二选一保留（或统一收敛为新的 db 访问模块），全项目仅一个数据访问入口 | P0 | 各路由 import 路径统一；删除冗余文件前须全局搜索确认无残留引用。 |
| R6 | 设置读取接口安全性：/api/settings 返回密钥时脱敏（如仅返回尾 4 位），密钥仅在服务端解密使用 | P1 | 本应用无登录系统，接口默认仅本机/局域网可信环境使用；是否加密存储由架构师评估（至少不明文回传给前端）。 |
| R7 | 数据一致性校验：迁移完成后输出校验报告（记录条数、字段抽样比对），校验通过后才切换读取源 | P1 | 防止迁移丢数据；建议保留 JSON 文件备份一段时间。 |
| R8 | 连接失败降级提示：数据库不可用时，前端给出明确错误提示，而非静默失败 | P1 | 健康检查接口（如 /api/health）可选。 |
| R9 | 设置变更即时生效：修改模型/密钥后无需重启服务 | P2 | 配置读取改为每次请求时读取或加失效机制。 |

## 5. 明确不做（Out of Scope）

1. **不引入用户系统/多租户**：当前为单人使用、全局共享数据的定位不变，不增加登录、注册、权限。
2. **不改 AI 功能逻辑**：转写、纪要 4 种风格生成、思维导图、待办提取、AI 问答、Word 导出的业务逻辑与提示词均不变。
3. **不改前端交互流程**：页面布局与操作路径不变，仅数据读写来源切换。
4. **不做云端部署/远程同步方案设计**：仍为本机自托管场景；数据库同机部署。
5. **不做历史数据的多版本/回收站**：删除即删除（维持现状），仅建议迁移前备份。
